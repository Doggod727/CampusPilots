### 1.3 原始需求解读原则

- 《06》给出的是长期产品全景，不等同于四人团队首期必须全部实现。
- 《10》明确说明功能按难度尽量完成、“不要求全部做完”，因此采用 MVP + 增量待办池管理。
- 技术适配示例（如 Chroma、bge-small-zh-v1.5）视为首选方案，不视为不可替换的业务约束；替换时必须保持接口和验收行为不变。
- 涉及教务、后勤、宿管、财务、心理咨询等校内系统的真实对接，在没有接口授权前一律使用适配器 + Mock 数据，不伪造“已对接”。
- 心理危机识别仅提供风险提示与人工升级，不进行医学诊断，不把生成式 AI 作为紧急救援主体。
- 复杂问答、跨领域答案生成与最终自然语言组织固定使用用户提供 API Key 的 `deepseek-v4-pro`；本地不部署同量级大模型。
- 本地仅运行小型指令模型和 RAG 重排模型，用于意图路由、结构化任务抽取、低成本推理与检索重排；默认模型规模不超过 3B，并支持量化或 CPU 降级。
- 模型微调仅针对可本地部署的小型开源指令模型，采用 LoRA/QLoRA 等参数高效方法；不宣称对 DeepSeek 托管模型权重进行微调。
- Agent、Tool 和 MCP 只是业务能力的调用入口，不能绕过 M1–M4 的权限、校验、幂等、审计与状态机。

## 2. 产品定义

### 2.1 产品定位

系统是面向在校学生、学校职能部门和平台运营人员的校园生活统一入口。学生通过自然语言或场景化入口获取校园政策与生活信息、办理事项、提交服务请求、参与校园社区；工作人员通过知识维护、内容治理、服务处理和数据看板持续改善校园服务。

### 2.2 核心问题

1. 校园政策、通知、办事指南和生活信息分散，学生“不知道去哪里找”。
2. 复杂事务缺少清晰材料、步骤、联系人和进度说明，学生“知道要办但不会办”。
3. 校园社区、朋辈经验、二手与失物信息割裂，资源匹配效率低。
4. 学校缺乏对高频诉求、知识盲区、服务质量和内容风险的统一观察窗口。

### 2.3 产品目标

- G1：提供有来源、可追溯、会兜底的校园知识问答。
- G2：把常用生活服务和事项办理收敛到统一入口。
- G3：形成可信、可治理的校园互动与互助空间。
- G4：形成知识维护、用户反馈、效果评估、持续优化闭环。
- G5：通过契约优先和模块化边界，使 4 名开发者能够围绕 5 个模块并行开发、独立测试、稳定联调。
- G6：形成可观测、可评估、可人工确认的校园多智能体系统，使 M1–M4 能以 Tools/MCP 方式被 M5 安全编排。
- G7：通过本地小模型、RAG 重排和参数高效微调降低硬件要求与大模型调用成本，同时保留复杂任务的回答质量。

### 2.4 首期成功指标

| 指标 | MVP 目标 | 统计口径 |
|---|---:|---|
| 标准问题命中率 | ≥ 80% | 冻结测试集内能返回相关答案且引用正确的问题占比 |
| 引用可用率 | 100% | 非兜底 RAG 答案至少含 1 个可打开的来源 |
| 高优先级流程完成率 | ≥ 90% | 报修、办事指南、失物发布等核心流程成功提交占比 |
| API 契约通过率 | 100% | OpenAPI 校验和前端契约测试中的 P0 接口 |
| 核心代码测试覆盖率 | ≥ 70% | 后端核心 service/domain 层行覆盖率 |
| 非 LLM API P95 | < 500 ms | 本地验收数据量、排除文件上传和异步任务 |
| 用户可感知首包时间 | < 2 s | Chat SSE 首个 `delta` 事件，Mock/可用模型环境下 |
| Agent 模块路由准确率 | ≥ 85% | 冻结意图测试集中首选专业 Agent 正确的样本占比 |
| Tool 调用成功率 | ≥ 95% | 排除主动拒绝、无权限和外部依赖故障后的 Tool 调用 |
| 写操作确认率 | 100% | 报修、报名、发布、审核等 Agent 发起的写操作均有确认记录 |
| 多智能体终止率 | 100% | 所有运行在最大步数或超时内完成、降级或明确失败，不出现无限循环 |

## 3. 用户角色与权限边界

| 角色 | 核心诉求 | 允许的主要操作 |
|---|---|---|
| 普通学生 | 咨询、办事、报修、互动、交易、失物、反馈 | 访问本人数据；发布与管理本人内容；不能查看他人隐私数据 |
| 学生干部/内容协作者 | 维护活动、专题与经验内容 | 在授权分区内创建和编辑内容，不能执行平台级配置 |
| 辅导员/服务处理员 | 处理学生服务、查看授权范围内风险提示 | 仅查看职责范围内工单与必要信息，禁止浏览无关心理倾诉原文 |
| 部门知识管理员 | 维护本部门知识资产 | 管理被授权知识库、文档、版本和发布状态 |
| 社区运营员 | 内容审核与社区运营 | 审核、下架、置顶、封禁；匿名内容默认不可反查真实身份 |
| 平台管理员 | 账号、角色、模型、系统与审计管理 | 平台级配置；高风险操作二次确认并写入审计日志 |
| 审计/观察角色 | 查看合规与运行记录 | 只读访问脱敏日志和统计，不得修改业务数据 |
| 模型工程管理员 | 管理数据集、训练任务、模型版本和评估结果 | 只能访问经授权和脱敏的训练数据；模型启用、回滚与导出均写审计日志 |

## 4. 范围管理

### 4.1 MVP 范围（首期必须完成）

MVP 按 5 个低耦合业务域划分。M1–M4 保留原有独立业务闭环；M5 通过公开 Tool 契约编排这些能力，不直接写入其他模块的数据表。

| 模块 | MVP 业务能力 | 独立验收输出 |
|---|---|---|
| M1 AI 知识与对话 | 使用预置知识完成检索、RAG 问答、引用、兜底和 SSE；提供 `knowledge.search` Tool | Agent 可取得带来源的校园知识；知识库完整管理界面进入 P1 |
| M2 校园服务中心 | 办事指南查询、宿舍报修创建/查询、电费余额查询和模拟充值申请 Tools | Agent 可查询指南、创建报修、查询进度、查询电费并创建不涉及真实支付的模拟充值申请 |
| M3 校园社区与互助 | 活动查询/报名、失物发布/查询/匹配 Tools | Agent 可完成活动报名和失物匹配；通用帖子、评论、点赞后台进入 P1 |
| M4 平台治理与基础能力 | 演示账号登录、最小 RBAC、Tool 授权、写操作确认、安全策略和审计 | Agent 调用具有统一身份、权限、安全与审计；完整用户/角色管理和看板进入 P1/P2 |
| M5 智能体与模型工程 | 意图路由、Tool 注册与调用、写操作确认、多智能体 P0 协作、数据集/模型版本、评估、轨迹与安全护栏 | 可由主管 Agent 路由到 M1–M4 专业 Agent，完成查询或经确认的业务操作，并查看完整执行轨迹 |

### 4.2 增量范围（MVP 后按优先级实现）

- P1：完整知识库管理、文档上传/发布、部门联系人、维修评价、通用帖子/评论/点赞/举报、活动发布、完整审核管理、用户/角色后台、基础看板；智能填单、真实办事进度适配器、二手交易、积分、个性化推荐、知识版本回滚、混合检索、对话质量评估；MCP 工具网关、本地 RAG 重排、小型指令模型 LoRA/QLoRA 微调；Agent 间任务交接、并行 Agent 执行与小模型路由。
- P2：学习搭子/一对一朋辈咨询、租借/拼单、志愿时长、推理诊断、自动回归测试、多模态输入、长期记忆、动态规划与反思。
- P3/研究性：真实支付、跨部门自动流转、复杂 Pandas Agent、心理危机联动、全量学工态势感知、动态创建 Agent 与无人工确认的自治执行。

### 4.3 明确不在首期范围

- 不接管学校教务、财务、门禁、心理咨询等系统的真实生产写操作。
- 不保存银行卡、支付密码等支付敏感信息，不自建资金托管。
- 不做心理疾病诊断、治疗建议或完全自动化危机处置。
- 不开放 LLM 生成代码在主机直接执行；Pandas 分析若实现，必须置于受限沙箱。
- 不以“展示全部长期功能菜单”作为完成标准；未实现入口不得造成可点击但无结果的假功能。
- 不在本地运行 DeepSeek V4 Pro 同量级模型，不从零预训练大语言模型，不把远程 API 调用描述为本地模型训练。
- 不允许 Agent 自由访问数据库、任意 URL、主机文件或未注册工具；不允许通过自然语言绕过 RBAC 与业务状态机。
- 不实现无限循环讨论、动态创建任意 Agent 或未经用户确认的高风险写操作。

## 5. 总体业务流程

### 5.1 RAG 咨询主流程

1. 学生创建或继续会话并提交问题。
2. 系统完成认证、限流、输入安全检查和意图识别。
3. 系统结合会话上下文重写查询，并在用户有权访问的知识库中检索。
4. 结果低于阈值时进入兜底；达到阈值时生成回答并保留引用映射。
5. 后端通过 SSE 依次发送元数据、文本增量、引用、完成或错误事件。
6. 系统持久化问题、答案、模型、耗时、检索结果摘要和请求 ID。
7. 学生可点赞、点踩或提交修正建议，反馈关联到会话与消息。

### 5.2 文档入库主流程

1. 知识管理员创建知识库并选择默认 Embedding 与切分规则。
2. 上传 txt/docx/pdf/md 文件；系统校验格式、大小、哈希和访问权限。
3. 文件进入异步任务：解析 → 清洗 → 切分 → 向量化 → 建立索引。
4. 每一步写入状态和错误原因；失败任务可重试，不产生半完成的可检索版本。
5. 管理员预览 Chunk、元数据与来源位置后发布文档。
6. 只有已发布且未过期文档进入学生端检索范围。

### 5.3 校园服务主流程

1. 学生从场景入口或 AI 推荐进入办事指南/报修。
2. 系统根据校区、学生类型和事项类型返回步骤、材料、地点、时间与联系人。
3. 报修场景通过结构化表单收集宿舍、故障类型、描述和可维修时段。
4. 工单提交采用幂等键防止重复创建，并进入状态机。
5. 处理员更新状态；学生只能查询本人或本人宿舍授权的工单。

### 5.4 社区和失物主流程

1. 用户提交帖子、评论、活动或失物信息。
2. 内容经过格式校验、敏感词检查和风险分级。
3. 低风险内容按策略发布，高风险内容进入人工审核。
4. 失物记录以类别、地点、时间和文本/图片特征生成候选匹配，仅通知候选双方，不公开私人联系方式。
5. 用户可举报，运营员按审核状态机处置，所有处置写审计日志。

### 5.5 M5 智能体调用主流程

1. 用户请求进入 M5，完成认证、限流、输入安全检查并生成 `agent_run_id`。
2. 本地小型指令模型优先完成意图分类；置信度低于阈值时，调用 `deepseek-v4-pro` 进行路由兜底。
3. Supervisor Agent 根据意图选择 M1 知识 Agent、M2 服务 Agent、M3 社区 Agent、M4 治理 Agent或 M5 ModelOps Agent。
4. 专业 Agent 只能从自身 Tool 白名单中选择能力；Tool 通过统一 Schema 调用对应模块 Service，不直接访问其他模块数据库。
5. 查询类 Tool 可自动执行；报修、报名、发布、审核、模型启停等写操作必须先生成确认卡片，用户确认后才执行。
6. 跨模块任务最多拆分为 3 个子任务，整个运行最多 6 个 Agent/Tool 步骤；达到超时或步数上限时返回已有结果并明确降级。
7. 复杂问答、跨 Agent 结果合并和最终自然语言回答由 `deepseek-v4-pro` 完成；本地模型不承担复杂答案生成。
8. 系统持久化路由、Agent、Tool、确认、耗时、Token、模型版本、结果状态和脱敏错误，不保存密钥与不必要的敏感原文。

### 5.6 本地模型训练与评估流程

1. 模型工程管理员创建数据集版本，上传或选择已脱敏的 JSONL/CSV 样本。
2. 系统执行格式校验、标签校验、重复检测、敏感信息扫描，并冻结训练/验证/测试划分。
3. 管理员选择不超过 3B 的小型开源指令模型、LoRA/QLoRA 参数和资源上限后创建异步训练任务。
4. 训练任务记录配置、随机种子、依赖版本、指标和产物地址；失败可诊断、可重试，不覆盖已有模型版本。
5. 训练产物进入模型注册表并处于 `candidate` 状态，必须完成离线评估后才能启用。
6. 评估至少覆盖意图路由准确率、低置信召回、推理延迟和内存占用；RAG 重排模型额外评估 Recall@K/MRR 或冻结测试集排序指标。
7. 模型启用、停用和回滚写入审计日志；未达到阈值时继续使用规则/DeepSeek 路由兜底。

### 5.7 契约优先开发顺序

1. 第一步只建立 M5 公共契约、Tool 注册中心、Agent 输入输出结构和 Mock Tools，不先实现完整多智能体。
2. 第二步并行完成 M1–M4 的领域 Service、REST API、Tool 适配器和模块测试。
3. 第三步冻结 Tool Schema，以真实 Tool 替换 M5 Mock，完成 Supervisor 与专业 Agent 的 P0 协作。
4. 第四步实现 P1 的 MCP 网关、RAG 重排、小模型微调、Agent 交接、并行执行与小模型路由。
5. REST、Tool 与 MCP 只作为适配器，共享同一领域 Service，禁止复制三套业务逻辑。

## 6. 功能需求与验收标准

### 6.1 M1 AI 知识与对话

| ID | 优先级 | 需求 | 可验收标准 |
|---|---|---|---|
| KB-001 | P1 | 创建、查询、编辑、逻辑删除知识库；按知识库隔离数据 | 名称唯一；删除前检查引用；无权限访问返回 403 |
| KB-002 | P1 | 批量上传 txt/docx/pdf/md，显示处理进度 | 非法格式返回 415；重复文件可识别；任务状态可轮询 |
| KB-003 | P1 | 解析、清洗、递归切分并生成向量 | Chunk 包含 `chunk_id/document_id/source_location/page_number` 等元数据 |
| KB-004 | P1 | 文档列表、预览 Chunk、发布/停用、删除 | 停用后新会话不可检索；删除同步清理索引 |
| CHAT-001 | P0 | 单轮知识问答 | 标准问题返回答案、消息 ID 和至少一个引用，否则明确兜底 |
| CHAT-002 | P0 | 多轮上下文 | 在配置轮数内能解析“这个/上一条”等指代；支持清空会话 |
| CHAT-003 | P0 | 流式响应 | 按统一 SSE 事件协议发送；断流可识别，最终状态可查询 |

### 7.2 数据规则

- 所有主键采用不可枚举的 UUID；对外不得暴露数据库自增规律。
- 所有时间以 UTC 存储，以 ISO 8601 返回，前端按 Asia/Singapore 展示。
- 所有业务表包含 `created_at/updated_at`；需要逻辑删除的表增加 `deleted_at`。
- 个人敏感信息按最小必要原则收集；日志禁止记录密码、令牌、完整身份证号、完整联系方式和心理倾诉原文。
- 匿名是对其他用户匿名，不是无审计责任；身份映射单独保护并设置高权限访问。
- 文档、图片等对象存储只保存对象键，下载使用短期签名地址或受权代理接口。
- 首期关系数据库采用 PostgreSQL；向量数据采用 Chroma（本地开发）并通过仓储接口隔离，便于后续迁移。
- Agent 上下文只保存完成任务所需的最小信息；Agent 间交接优先传递结构化摘要，不复制完整会话和敏感业务对象。
- 训练数据必须记录来源、授权、脱敏状态和版本；生产/演示用户原始对话不得未经审核自动进入训练集。
- 模型二进制、Adapter 和评估报告存对象目录，数据库只保存元数据、对象键和完整性哈希。
- Tool 调用参数和结果按字段级策略脱敏；写操作保存确认快照哈希，保证执行参数与用户确认内容一致。

## 8. API 契约需求（联调基线）

### 8.1 契约优先

1. 在编写前后端业务实现前冻结 `openapi.yaml`；后端实现、前端 TypeScript 客户端、Mock Server 和契约测试均由它驱动。
2. API 前缀统一为 `/api/v1`；内部模块接口使用 `/internal/v1`，不得从浏览器直接访问。
3. FastAPI 的 `/openapi.json` 必须与仓库内契约一致，CI 检测不兼容变更。
4. 每个接口必须定义：operationId、认证、参数、请求体、成功响应、错误响应、示例和权限要求。
5. 对已发布接口禁止直接删除字段或改变含义；破坏性变更必须升级 API 主版本。
6. M1–M4 在实现 REST API 前先冻结领域 Service 与 Tool Schema；REST、内部 Tool 和 MCP 适配器必须映射到同一业务命令/查询对象。
7. Tool 必须声明 `name/version/module/input_schema/output_schema/required_permissions/risk_level/timeout_ms/idempotent`；M5 不接受无 Schema 的自由参数调用。
8. MCP 是 P1 适配层，不能成为 M1–M4 唯一调用入口；即使 MCP 未完成，内部 Tool 和 REST 仍可独立验收。

### 8.2 通用请求约定

- 内容类型：普通接口 `application/json; charset=utf-8`；上传使用 `multipart/form-data`；流式聊天使用 `text/event-stream`。
- 认证：`Authorization: Bearer <access_token>`。
- 链路：客户端可传 `X-Request-Id`，后端必须在响应中返回；未传则后端生成。
- 幂等：创建工单、报名、反馈等易重复写接口支持 `Idempotency-Key`。
- Agent 写操作：除业务幂等键外还必须传递 `agent_run_id/approval_id`；批准内容与执行参数哈希不一致返回 409。
- 分页：`page` 从 1 开始，`page_size` 默认 20、最大 100；响应返回 `items/page/page_size/total`。
- 排序：只接受接口白名单字段，格式 `sort=-created_at,name`。
- 日期：统一 RFC 3339/ISO 8601；枚举值使用稳定英文小写编码，中文仅用于展示。

### 8.3 通用响应与错误

成功响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "01J...",
  "timestamp": "2026-07-12T06:00:00Z"
}
```

错误响应：

```json
{
  "code": "WORK_ORDER_INVALID_TRANSITION",
  "message": "当前状态不能执行该操作",
  "details": [{"field": "status", "reason": "completed_to_processing"}],
  "request_id": "01J...",
  "timestamp": "2026-07-12T06:00:00Z"
}
```

HTTP 状态语义：400 参数语义错误；401 未认证；403 无权限；404 资源不存在；409 状态/幂等冲突；413 文件过大；415 格式不支持；422 字段校验失败；429 限流；500 系统错误；502/504 外部依赖失败或超时。

### 8.4 SSE 事件协议

聊天流必须按以下顺序发送，前端不得通过解析自然语言猜测状态：

| event | data 必需字段 | 用途 |
|---|---|---|
| `meta` | `conversation_id,message_id,request_id` | 建立消息关联 |
| `delta` | `sequence,content` | 文本增量，可出现多次 |
| `sources` | `citations[]` | 引用列表，含文档和定位信息 |
| `done` | `finish_reason,usage` | 正常完成 |
| `error` | `code,message,retryable` | 异常终止 |

SSE 断线后，客户端通过消息详情接口查询最终状态；服务端不得在同一消息上重复扣费或重复持久化。

M5 Agent 流在上述通用事件外增加以下事件；前端必须按 `sequence` 去重和排序：

| event | data 必需字段 | 用途 |
|---|---|---|
| `route` | `agent_run_id,target_agent,confidence,source` | 展示路由结果；`source` 为 `local_model/deepseek/rule` |
| `agent_step` | `step_id,agent_id,status,sequence` | 展示专业 Agent 执行进度 |
| `tool_call` | `step_id,tool_name,status,duration_ms` | 展示脱敏的 Tool 调用状态，不返回敏感参数 |
| `approval_required` | `approval_id,action,summary,expires_at` | 请求用户确认写操作 |
| `handoff` | `from_agent,to_agent,status` | P1 展示 Agent 间任务交接 |

## 9. 非功能性需求

### 9.1 性能与容量

- 非 LLM 普通查询 API 在验收数据量下 P95 < 500 ms。
- 列表均分页；数据库查询不得出现明显 N+1；常用过滤字段建立索引。
- 大文件解析、向量生成、批量导出通过异步任务执行，HTTP 请求只返回任务 ID。
- Chat SSE 首包目标 < 2 秒；完整生成时间单独计量，不混入普通 API 指标。
- 参考目标：1 GB PDF ETL 在 1 小时内完成，首期允许以缩小数据集验证并记录外推结果。
- 本地小模型路由在验收机器热启动状态下 P95 < 500 ms；模型未加载时允许规则路由并异步预热。
- RAG 重排默认只处理初始召回 Top 20，验收机器 P95 额外延迟目标 < 1 s；超时自动返回未重排结果。
- 单个 Agent 运行最多 6 步、最多 3 个专业 Agent；P1 并行执行默认最大并发 3，均可通过配置下调。
- 训练任务必须异步执行并配置 CPU、内存、显存、时长和磁盘上限；资源不足时拒绝排队或给出可诊断失败，不影响在线问答。

### 9.2 可用性与可恢复性

- 外部模型或校园系统失败时返回明确可重试状态，不让整个站点不可用。
- 异步任务支持幂等重试和失败原因查看。
- 数据库每日备份策略、恢复演练步骤进入部署文档；MVP 至少验证一次本地备份恢复。
- DeepSeek 不可用时，复杂问答返回明确降级提示；不得让本地小模型伪装成同等能力的大模型继续生成高风险答案。
- Agent 运行状态、人工确认和并行子任务支持断线后查询；重试不得重复执行已经成功的非幂等 Tool。
- 本地模型加载失败时自动回退到规则或 DeepSeek 路由；RAG 重排失败时回退到原始召回排序。

### 9.3 安全与隐私

- 密钥仅通过环境变量或密钥服务注入，不写入仓库、日志和前端包。
- 密码使用成熟的自适应哈希算法；JWT 短时 access token + 可撤销 refresh token。
- 入口执行大小限制、文件类型嗅探、速率限制、参数校验和输出编码。
- 文件上传需防路径穿越，文件名不作为存储路径；可疑文件拒绝或隔离。
- 代码执行类 Agent 必须在无宿主文件权限、无默认网络、有限 CPU/内存/时长的沙箱中运行。
- 心理、宿舍、门禁、消费、匿名身份映射等数据采用更严格权限、脱敏展示和更短留存。
- 危机提示必须展示人工渠道和紧急联系方式；具体联系人、通知条件、值班机制需学校确认后才能启用。
- Agent 执行器对 Tool 采用拒绝优先和最小权限白名单；专业 Agent 只能看到与其模块相关的 Tool。
- MCP Server 仅接受受信客户端和服务身份，默认不向公网开放；Tool 发现结果按调用者权限过滤。
- 来自知识库、社区内容和 Tool 返回值的文本均视为不可信数据，不能覆盖系统指令、权限与确认策略。
- 训练数据进入数据集前必须脱敏并记录授权；模型产物不得打包真实密钥、访问令牌或可还原的敏感样本。

### 9.4 可维护性与质量

- Python 代码启用类型标注；前端开启 TypeScript 严格模式。
- 后端核心业务测试覆盖率不低于 70%；每个 P0 API 至少包含成功、认证、权限、校验和冲突测试。
- 使用结构化 JSON 日志，至少包含 request_id、user_id（可脱敏）、module、operation、duration_ms、status。
- 所有合并通过 Pull Request 和至少 1 人 Code Review；数据库迁移和 OpenAPI 变更必须单独标注。
- 新增功能同时更新 OpenAPI、迁移、测试、README 和变更记录，否则不满足完成定义。
- 每个 P0 Tool 至少具有 Schema、权限、参数校验、成功、业务失败、超时和幂等/确认测试。
- 多智能体测试必须覆盖单 Agent、跨模块、最大步数、循环检测、子任务部分失败、用户拒绝确认和断线恢复。
- 模型训练与评估记录包含数据集版本、配置、随机种子、代码版本和指标，能够复现实验或明确说明不可复现原因。

### 9.5 可访问性与体验

- 桌面端优先并适配移动浏览器；核心流程无需横向滚动。
- 表单提供明确标签、校验提示与错误恢复；不能只用颜色表达状态。
- AI 生成内容明确标识；引用、风险提示和人工入口必须可见。
- Markdown 渲染默认禁用危险 HTML，外链使用安全属性，防止 XSS。

## 11. 四人五模块低耦合分工

M1–M4 仍由四人一人一个业务模块。M5 不增加第五名成员，按内部子域拆分，并在 M1–M4 核心闭环完成后集中集成。

| 成员 | 主责模块 | M5 次责 | 仓库边界与主要契约 |
|---|---|---|---|
| A | M1 AI 知识与对话 | `modelops`：本地小模型、LoRA/QLoRA、RAG 重排 | `backend/modules/ai_knowledge`；Knowledge/Chat/Ingestion API 与 `knowledge.*` Tools |
| B | M2 校园服务中心 | `tool_gateway`：Tool Schema、注册适配、P1 MCP 网关 | `backend/modules/campus_service`；Guide/WorkOrder API 与 `service.*` Tools |
| C | M3 校园社区与互助 | `orchestration`：Supervisor 子图、任务分解、P1 交接/并行 | `backend/modules/community`；Post/Event/LostFound API 与 `community.*` Tools |
| D | M4 平台治理与基础能力 | `runtime`：权限、确认、轨迹、安全护栏、评估元数据 | `backend/modules/platform`；Auth/Moderation/Audit API 与 `governance.*` Tools |

M5 共享仓库边界为 `backend/modules/agent_platform/{orchestration,tool_gateway,modelops,evaluation}` 和 `frontend/modules/agent-platform`。每个子目录有明确 CODEOWNER；跨子域公共 Schema 只能通过评审修改。

协作规则：

1. 采用模块化单体起步，而非五套微服务；每个模块有独立 router/service/repository/schema/migration 分区。
2. 跨模块只能调用公开 service 接口、内部 API 或领域事件，禁止跨模块直接写数据库表。
3. 用户身份由 M4 生成统一认证上下文；业务模块只消费 `user_id/roles/permissions`，不自行实现登录。
4. 审核由 M4 管状态和处置，M3 保留内容事实；审核结果通过接口/事件回写内容可见状态。
5. 每人维护本模块 OpenAPI 标签、Mock 数据、迁移和测试；共享基建变更需小组评审。
6. 每个 Sprint 轮换 1 名集成值班人，负责主干健康、契约差异和端到端冒烟，不替代模块负责人。
7. M1–M4 模块负责人必须在领域 Service 之上提供 Tool Adapter；M5 只依赖稳定 Tool Schema，不依赖具体 router/repository。
8. M5 公共 `AgentTask/AgentResult/ToolDefinition/ToolCallResult/AgentHandoff` Schema 在第 1 天冻结；修改需四人共同评审。

## 12. 敏捷开发计划

项目采用 Scrum，开发窗口固定为 10 天，作为一个完整 Sprint 管理。每天进行不超过 15 分钟的 Daily Scrum，第 1 天进行 Sprint Planning，第 10 天进行 Sprint Review 与 Sprint Retrospective。

| Sprint | 目标 | 关键交付 |
|---|---|---|
| 第 1 天 | 契约与骨架冻结 | M5 公共 Schema、Tool 注册中心、Mock Tools；五模块骨架、OpenAPI/ERD 初稿、Compose、CI |
| 第 2–4 天 | M1–M4 事件能力与 Tool 化 | 使用种子账号/知识，完成 RAG、指南、报修、电费查询/模拟充值、活动报名、失物匹配、安全/审计 Tools；通用管理后台不阻断 |
| 第 5 天 | 模块测试与 Tool 契约冻结 | M1–M4 P0 模块测试；冻结 Tool Schema、权限、错误、幂等和确认元数据 |
| 第 6 天 | M5 接入真实 Tools | 用真实 Tools 替换 Mock；完成 Supervisor、专业 Agent 注册、自动调用和运行轨迹 |
| 第 7 天 | 多智能体 P0 闭环 | 完成 MA-001～MA-007、写操作确认、安全护栏、超时/循环限制和跨模块演示 |
| 第 8 天 | 模型工程与 P1 试做 | 数据集/模型/评估 P0；试做本地重排、LoRA/QLoRA、MA-008～010，不阻断 P0 验收 |
| 第 9 天 | MCP、全量测试与交付整理 | 试做查询类 MCP；契约、权限、Agent、端到端与性能测试；修复、README、SQL、报告 |
| 第 10 天 | Sprint 验收 | Sprint Review、Retrospective、演示和彩排、版本封板 |

### 12.1 Definition of Ready

一个故事进入开发前必须具备：用户价值、业务规则、权限、验收标准、原型或交互说明、OpenAPI 变更、依赖和测试数据。涉及 Agent/Tool 时还必须具有 Tool Schema、风险级别、是否需要确认、超时/幂等规则和 Mock 响应。

### 12.2 Definition of Done

完成意味着：实现通过；迁移可执行；OpenAPI 与实现一致；单元/接口测试通过；前端无手写重复模型；异常状态可展示；日志与权限到位；PR 完成评审；README/变更记录已更新。Agent 需求还必须通过最大步数、权限、确认、Tool 失败、部分失败和降级测试；模型需求必须绑定数据集/模型版本及评估结果。

## 14. 风险、依赖与已确认决策

### 14.1 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 长期需求过大 | 延期、功能半成品 | 冻结 MVP；未实现功能不进首期导航 |
| 校内系统无接口/无授权 | 进度、水电、门禁无法真实对接 | 适配器 + Mock；接口获批后替换实现 |
| RAG 幻觉或政策过期 | 误导学生 | 只检索已发布内容、强制引用、有效期、低置信兜底 |
| 匿名与心理数据泄露 | 严重隐私/伦理风险 | 最小收集、分级权限、脱敏审计、人工治理 |
| 四人同时改共享代码 | 冲突与联调失败 | 模块边界、契约优先、生成客户端、集成值班 |
| 本地模型环境差异 | 成员无法启动 | Mock LLM + 远程 API + 可替换 Provider |
| Agent 代码执行 | 主机和数据安全风险 | MVP 禁用；后续仅沙箱、无网、限资源执行 |
| 五模块超出四人承载 | M5 挤压 M1–M4 核心闭环 | 第 1 天只做 M5 契约/Mock；M1–M4 完成后再集中集成；P1 不阻断验收 |
| Agent 循环或错误路由 | 延迟、费用增加、误操作 | 最大 6 步、最多 3 个 Agent、循环检测、本地低置信兜底与人工确认 |
| Prompt/Tool 注入 | 越权访问或错误写入 | Tool 白名单、Schema 校验、业务权限二次校验、不信任 Tool/知识文本 |
| 小模型准确率不足 | 错误路由影响体验 | 冻结评估集、置信阈值、规则/DeepSeek 兜底、模型版本回滚 |
| 本地训练资源不足 | 微调和重排无法演示 | 模型不超过 3B、LoRA/QLoRA、量化/CPU 降级、训练 P1 且可使用预生成产物 |
| MCP 扩大攻击面 | 未授权工具被外部调用 | P1 默认查询类、仅受信客户端、服务身份、权限过滤与审计；不向公网开放 |

### 14.2 已确认决策

| 编号 | 决策项 | 确认结论 | 状态 |
|---|---|---|---|
| D1 | 开发周期与 Scrum 节奏 | 10 天，一个 Scrum Sprint，每日站会 | 已确认 |
| D2 | MVP 范围 | 保留 M1–M4 全部需求并新增 M5；不要求 12 大长期模块全部实现 | 已确认 |
| D3 | 身份认证 | 首期使用内置测试账号、密码登录和 JWT，不对接学校统一认证 | 已确认 |
| D4 | 校内业务系统 | 全部通过 Mock 适配器提供演示数据，前端接口保持可替换 | 已确认 |
| D5 | LLM 与 Embedding | 固定 `deepseek-v4-pro`；用户提供 API Key；Embedding 使用 `bge-small-zh-v1.5` | 已确认 |
| D6 | 部署方式 | Docker Compose 单机部署，用于本地/答辩演示 | 已确认 |
| D7 | 心理危机演示边界 | 不自动通知真实人员，仅展示经过审核的求助渠道与风险提示 | 已确认 |
| D8 | 数据治理演示边界 | 留存期限、匿名反查审批仅做可配置项，不填真实生产策略 | 已确认 |
| D9 | M5 AI 能力 | 新增 AI-01/02/03/04/05/09/10/11/12/13/15/16/19 | 已确认 |
| D10 | 多智能体范围 | MA-001～007 为 P0；P1 仅增加 MA-008、MA-009、MA-010 | 已确认 |
| D11 | 模型运行边界 | 复杂问答固定调用 `deepseek-v4-pro`；本地只运行小型指令模型和 RAG 重排模型 | 已确认 |
| D12 | 微调边界 | 只对不超过 3B 的本地开源指令模型进行 LoRA/QLoRA，不对 DeepSeek 托管权重做本地微调 | 已确认 |
| D13 | 实施顺序 | M5 契约/Mock 先行，M1–M4 领域与 Tool 完成后再接入 M5，最后实现 MCP/微调/MA P1 | 已确认 |

## 15. 本阶段评审结论

V2.1 需求基线已按用户选择完成重构，M1–M4 原需求全部保留但重新排序，M5、AI、多智能体和首期事件型 Tools 范围已固定。下一阶段先更新概要设计中的五模块边界、Agent/Tool/MCP 架构、本地模型部署和契约优先开发拓扑；随后完成 M5 详细设计并回补 M1–M4 Tool Adapter 设计。
