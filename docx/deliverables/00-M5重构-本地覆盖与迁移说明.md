版本：V1.0  
日期：2026-07-15

## 1. 覆盖范围

本覆盖包保留 M1～M4 全部原需求，并把开发重心调整为 M5。需要整体覆盖以下设计基线：

1. `01-需求分析说明书.md`：V2.1，新增 M5、AI-01/02/03/04/05/09/10/11/12/13/15/16/19 与 MA 优先级。
2. `02-概要设计说明书.md`：V1.0，改为 M5 优先、M1～M4 事件 Tool 化的总体架构。
3. `03-详细设计说明书-Part1-公共基础与平台治理.md`：V0.11，补 M5 权限、内容 scope、审计和旧 JWT 兼容。
4. `03-详细设计说明书-Part2-M2校园服务中心.md`：V1.0，补指南/报修/电费 5 个 Tool Adapter。
5. `03-详细设计说明书-Part3-M1-AI与知识库.md`：V1.0，补知识检索与回答 Tool Adapter、RAG Reranker Port。
6. `03-详细设计说明书-Part4-M3校园社区与互助.md`：V1.0，补活动与失物 4 个 Tool Adapter。
7. `03-详细设计说明书-Part5-M5智能体与模型工程.md`：V0.2，给出 6 Agent、14 Tool、编排、确认、模型工程和测试设计。
8. `openapi.yaml`：V0.5.0，100 个路径、136 个唯一 operationId。
9. `redocly.yaml`：本地演示环境对应的 lint 规则。
10. `sql/001`～`sql/013`：包含完整建库顺序，其中 009～013 为本次新增的 M5 兼容、电费演示和 Agent Platform 增量。

包内不包含 DOCX，也不修改原始参考文档。

## 2. 推荐覆盖方式

解压后，把包内 `deliverables/` 目录合并覆盖到项目原 `deliverables/`。001～008 随包提供用于完整校对，009～013 是追加迁移；已执行过的数据库不要回退重跑旧迁移。

覆盖前建议提交或备份现有修改；覆盖后先查看差异，再提交：

```bash
git status --short
git diff -- deliverables
```

执行迁移后必须重新登录或刷新 Token。旧 JWT 不包含新权限时，Agent/Tool 接口会返回 403，这不是 M4 数据损坏。

```env

DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_API_KEY=<自行提供，不提交 Git>
LOCAL_ROUTER_MODEL_PATH=/models/router
RERANKER_MODEL_PATH=/models/reranker
MODEL_ARTIFACT_ROOT=/data/models
DATASET_ARTIFACT_ROOT=/data/datasets

```

演示阶段复杂问答固定调用 DeepSeek；本地仅允许小型指令模型、Embedding 和 RAG Reranker。P1 微调仅针对 3B 及以下开源模型，不微调 DeepSeek 托管权重。

## 5. M4 已开发完成时的影响

不会要求重写 M4。需要注意四个兼容点：

- 先执行 009，否则 `tool_input/tool_output/agent_context` 或 `agent_platform` 会触发旧 CHECK 约束错误。
- 旧 Token 刷新前缺少新权限，调用会得到 403。
- M5 必须通过治理 Tool/Service 调 M4，不能直接写 M4 表。
- 日志统一携带 `request_id -> run_id -> step_id -> tool_call_id/approval_id -> audit_id`，避免联调时无法关联。

## 6. 开发启动顺序

1. 先冻结 OpenAPI V0.5.0、Pydantic Tool Schema 与 009～013。
2. 用 14 个 Mock Tool 跑通 ToolExecutor、权限、确认和审计。
3. M1～M4 分别接入真实 Adapter，不改变既有领域表的写入边界。
4. 实现 Supervisor 与专业 Agent 的 P0 顺序编排、轨迹和 SSE。
5. 完成数据集、模型版本与评估 P0。
6. 最后试做 MCP、Reranker、LoRA/QLoRA、MA-008～010；P1 不阻断演示。

四人分工以 Part 5 第 16 节为准，公共契约变更必须先合并，成员分支不得各自复制 DTO。
