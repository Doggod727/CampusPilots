# 学生生活一站式社区 AI 助手——最终交付包（Markdown 版）

## 1. 模块编号

| 后缀 | 模块 | 负责人可独立开发的范围 |
|---|---|---|
| `+M1` | AI 与知识库 | 知识导入、检索增强生成、对话、反馈与 DeepSeek 接入 |
| `+M2` | 校园服务中心 | 服务目录、办事指南、工单、进度与评价 |
| `+M3` | 校园社区与互助 | 话题、帖子、评论、活动、失物招领与举报 |
| `+M4` | 公共基础与平台治理 | 用户、认证、权限、审计、内容治理及公共基础能力 |

需求分析、概要设计和 OpenAPI 为全项目共享文件，因此使用 `+M1-M4` 标识。

## 2. 建议阅读与实施顺序

1. 阅读 `01-项目依据` 中的原始任务要求。
2. 阅读 `02-总体设计/01-需求分析说明书+M1-M4.md`。
3. 阅读 `02-总体设计/02-概要设计说明书+M1-M4.md`。
4. 全组以 `03-API接口/API接口定义+M1-M4.yaml` 为唯一联调契约。
5. M4 先完成认证、用户、权限、审计和治理基础；M1、M2、M3 可随后并行开发。
6. 各模块开发者阅读相应目录的详细设计、SQL 与 ER 图。

## 3. 文件格式用途

- `.md`：供 Vibe Coding、代码生成、评审阅读与版本管理使用。
- `.yaml`：完整 OpenAPI 3 接口契约，可生成前后端客户端或 Mock。
- `.sql`：数据库建表与演示数据脚本，按编号顺序执行。
- `.png`：系统架构图、部署图和数据库 ER 图。

## 4. 数据库脚本执行顺序

1. `001-数据库结构+M4.sql`
2. `002-演示数据+M4.sql`
3. `003-数据库结构+M2.sql`
4. `004-演示数据+M2.sql`
5. `005-数据库结构+M1.sql`
6. `006-演示数据+M1.sql`
7. `007-数据库结构+M3.sql`
8. `008-演示数据+M3.sql`

> 当前 SQL 已完成结构校验；开发环境启动后仍应在 PostgreSQL 16 上实际执行迁移验证。

## 5. 开发前必须准备

- Python 3.12、Node.js、PostgreSQL 16、Redis、Docker/Compose。
- DeepSeek API Key；模型固定为 `deepseek-v4-pro`。
- `COMMUNITY_DATA_ENCRYPTION_KEY`，用于 M3 联系方式与认领证据加密。
- 本地向量模型 `bge-small-zh-v1.5` 与 Chroma 数据目录。
- 将 OpenAPI 契约导入接口工具，并优先生成前端 TypeScript 类型。
